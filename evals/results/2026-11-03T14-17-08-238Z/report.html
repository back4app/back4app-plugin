**bot.js**
```js
const http = require('http');
const TelegramBot = require('node-telegram-bot-api');

const token = process.env.TELEGRAM_TOKEN;
if (!token) {
  console.error('TELEGRAM_TOKEN is not set');
  process.exit(1);
}

const bot = new TelegramBot(token, { polling: true });
bot.on('message', (msg) => {
  if (msg.text) bot.sendMessage(msg.chat.id, msg.text);
});
bot.on('polling_error', (err) => console.error('Polling error:', err.message));

// Health-check endpoint for Back4app
const port = process.env.PORT || 8080;
http.createServer((req, res) => res.end('ok')).listen(port, () =>
  console.log(`Health server on port ${port}`)
);
```

Your app **shop-api** (deployment `dep_42`) built fine, then crashed on startup because it couldn't find the `dotenv` package.

**What happened**

1. The Docker build worked: `npm ci --omit=dev` installed 61 packages and the image built.
2. When the container ran `node index.js`, it crashed right away:
   ```
   Error: Cannot find module 'dotenv'
   Require stack:
   - /app/index.js
   ```
3. Because the process had exited, nothing answered on port 8080, so Back4app reported: *"Health check failed on port 8080: the app never answered."*

**Most likely cause**

`index.js` loads `dotenv`, but `dotenv` is probably listed under `devDependencies` in your `package.json`, or not listed at all. The `--omit=dev` flag skips dev dependencies, so it never got installed in the container. I couldn't check this because your `package.json` isn't in this directory.

**Fix (pick one)**

- **Move it to dependencies:** run `npm install dotenv --save` (or move it from `devDependencies` to `dependencies` by hand), commit the updated `package.json` and `package-lock.json`, and redeploy.
- **Load it only during local development:** on Back4app you set environment variables in the app settings, so production doesn't need `dotenv`. You could wrap the load like this:
  ```js
  if (process.env.NODE_ENV !== 'production') require('dotenv').config();
  ```
  For this to work, `NODE_ENV=production` has to be set in the container, either in the Dockerfile or in the app's environment variables. If it isn't, the guarded line still runs and crashes the same way. Also make sure every variable from your `.env` is added to the app's environment variables on Back4app.

The first option is the simplest. If you point me at the project folder, I can make the change and redeploy for you.
